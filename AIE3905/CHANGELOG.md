# 未发布（v0.3 第 1、3 阶段：AstrBot 原生前台、长记忆；记忆 v2：整天通读）

- 记忆 v2.2：写入时只做组织和忠实记录，裁决留到回答时。
  - 通读和整合不再给出别名、状态、重要度或“推翻”这类结论；长期记忆是按话题归类、带说话人和日期的记录，整合只接受 topic、record、person、term 四种操作。
  - 旧记录不再被隐藏，回复看到的是按时间排列的最近记录；话题排序只按最近出现时间、出现天数和记录条数计算，30 天没再提起就归档。
  - 回复引导和 memory 子 agent 使用同一条判断方法：以时间最新、说话人合适的说法为准，玩笑、假设、传闻、提问、转发不算结论，拿不准就列出几种可能和依据。
  - 通读提示要求挑要点、合并重复闲聊，不写流水账（否则 flash 会把一天写成超长流水并被截断）。
  - `tools/eval_memory.py` 改为按回答打分：回答模型只看回复时会注入的内容，按固定 JSON 回答五类问题（当前安排、同一性、负责人、未回答的问题、拒答），由程序对照标准答案；`--host` 复用测试台读取宿主模型，`--plugin` 可评测旧版本。新增留出集 `datasets/memory-hard-holdout`（种子 23）。
  - 评测结果见 `results/memory-eval-v22/`：v2.2 在负责人（0.94 对 0.69）和同一性上优于 v2.1；日终整合用 flash 时负责人一项低 8–17 个百分点（每天约 4 题，样本小），但在真实记录上 flash 多答对一题，且整合快约 10 倍、能复用通读缓存；试点群的整合改用 flash（`models.consolidating`）。
- 记忆 v2.1（据真实群聊评测修正）：
  - 当天目录和长期话题记录同一件事的不同叫法（别名），并在回复提示里显示；QA 清单新增“同一件事有哪些叫法”。
  - 规则、版本、名单这类会更新的东西每版写一条事实，同一天内的先后版本也用 `nf` 编号串成推翻关系；超过 120 字的事实拒收，不再截断；不记录对个人的议论。
  - 所有记忆工具的结果附带 `context`：今天的日期、记录覆盖的日期、相关长期话题及其别名和当前事实，让看不到注入内容的 memory 子 agent 也有全局参照。
  - 日期支持 `09-24`、`9.24`、`9/24`、`9月24`；重读找不到记录时说明记录覆盖的日期。
  - 群友向助手的提问在原文里标 `@助手`、在检索结果里标 `asked_bot`，不作为证据。
  - 其他机器人的斜杠命令只入库不回复；工具调用前单独的“我查一下～”不再发出；不承诺主动提醒；只对真正的重复提问作出反应。
  - 提取筛选：只有“今天、今晚、周六”这类相对时间词时不再放行，需同时出现安排类词或具体钟点、日期。
  - 日终整合单独使用 `memory.consolidate_timeout_seconds`（默认 420 秒），推理模型的整合不再在 180 秒处超时；通读和整合遇到不合法的 JSON 会重问一次，提示要求引用原话用「」。
  - 放宽工具调用前铺垫的识别（如“我先去把最近几天的记录翻一遍～”），合并到回答开头时也会去掉。
- 回复分快慢两档：配置 `dialogue.fast_provider` 和 `deep_provider` 后，日常 @ 用快模型（如不开思考的 flash）；消息里有“深入、仔细、详细、调研、研究、分析、查一下、对比、评估、总结”（`deep_keywords`）时才换成慢而强的模型并做深度调研。模型在收到消息时就选好，不增加等待。
- 记忆 v2：用整天通读取代每 30 条一批的话题摘要（`memory.reading`，默认开启；v3 话题摘要改为默认关闭，留作评测基线）。
  - 后台按新增字数或空闲时间通读当天全部群聊，整理成当天目录。提示按“固定指令与 QA 清单 → 只追加的当天全文 → 会变的部分”排列，重复通读时能命中前缀缓存；每次调用的缓存命中量记入 `usage.cached_tokens`。
  - 表情、笑声、复读先用规则合并；回复关系写在每行里。目录里的每个要点都必须引用真实的消息编号，不合格就保留上一版。
- 日终整合：每天 `consolidate_time`（默认 04:00）后，按 `config/qa_list.json` 逐条作答，生成日摘要；长期记录只接受由程序校验的操作。
  - 操作包括话题、决定、计划、事实、推翻、未决问题、成员分工、群里的说法和聊天风格；推翻只在同一话题内有效。
  - 话题按新近程度、重要度和出现天数排序；长期不提的话题休眠、归档；每周和每月各汇总一次。
  - 整合可以配置单独的、更强的模型（`models.consolidating`）。
- 每次 @：今天的话题、相关的长期记录和群里的说法放在提示最前面，全部来自数据库查询，不增加回复等待。
  - 新增 `get_topic_timeline`（某件事怎么定的、改过几次、现在以哪条为准，附原话）和 `read_group_day`（重读某一天的原始记录回答细节）。
  - `get_group_episodes` 改为：几天以内按话题列出，更长时间给日、周、月摘要。
  - 这些工具交给 memory 子 agent，它按“时间线 → 摘要 → 原话检索 → 重读某天”的顺序查找。
- 正式事项提取加筛选（`memory.gate`，默认开启）：只有像安排、决定、分工、时间的消息，或正在确认草案的消息才调用模型，其余标为 `gated`。
- 数据库迁移到 schema 4，只新增表和列。撤回、`/别记我`、到期清理时，只删除引用了该消息的要点、答案、事实、说法和成员印象；被推翻的旧事实恢复有效并标注“依据可能已变”；周摘要和月摘要删除后重新生成。
- 新增难题集 `tools/memory_hard.py`（默认 7 天、每天 1200 条）：每个计划都藏着看起来像结论的陷阱——假设、玩笑、谣言、转发的去年记录、发错后撤回的消息；还有被纠正的错误回答、转手的分工，同一件事白天晚上分两段聊、之后只用别名提起，闲聊里混进地点和钟点等干扰词。`--rewrite` 可用模型把消息改写得更口语，关键值不能丢，丢了就保留原文。评测新增“陷阱没被当成结论”“一件事只对应一个话题”两项。
- 新增 P0 评测：`lab.py days` 生成多天模拟群聊和标准答案；`tools/eval_memory.py` 按模拟时钟回放，给当天话题、决定、当前状态、历史、黑话、分工和拒答打分，可与 v3 话题摘要对比，并统计每千条消息的成本和缓存命中率。
- 沙盒改为检查：后台通读是否经宿主模型生成了当天目录并记录缓存命中量，@ 的提示是否先放记忆。
- 长记忆（第 3 阶段）：后台维护循环按“每 `memory.episode_size` 条，或空闲 `episode_idle_minutes` 分钟且不少于 `episode_min` 条”把群聊整理成话题摘要（episodes），并据此更新活跃成员的公开印象（profiles），只写在本群公开说过、做过的事。数据库迁移到 schema 3，只新增表。
- 摘要和印象都记录来源：撤回、`/别记我`、删除事项、过期清理时，引用了被删消息的摘要连同依赖它的印象一起删除；模型调用期间来源被撤回的，丢弃这次结果。摘要失败后退避 10 分钟再试。
- `search_group_history` 增加 `who`（按人）和 `when`（今天、上周、最近3天、10月3日等）过滤，结果附前后各 2 条原话和相关话题摘要；看不懂的时间或找不到的人会明确说明，不会猜。新增 `get_group_episodes`、`get_member_profile`。配置 `transfer_to_memory` 子 agent 后，这三个工具只交给它用。
- 主 agent 的提示里附上已滚出上下文窗口的最近 3 个话题摘要。
- 新增 `dialogue.frontend`（默认 `astrbot`）：配置群里 @ 的自然语言交给 AstrBot 主 agent 回答，可以使用宿主的人设、分段回复、子 agent 和联网搜索；每条消息仍然只回一次。`/问`、`/记事` 等命令照旧由插件严格处理。设为 `plugin` 可回退到 v0.2 自有对话。
- 插件在 `on_llm_request` 用自己的群记录替换宿主会话历史：最近 `context_messages`（默认 40）条群聊，包含 bot 之前的回复，以及当前发言人的引用和草案。撤回、退出记录和过期的内容不会再经由宿主历史进入模型。
- 新增宿主工具 `search_group_history`、`read_group_items`、`save_group_drafts`、`submit_group_events`。群和身份取自事件，模型无法指定，写入仍走原有校验。这些工具只在配置群的 @ 轮次提供；配置了 `transfer_to_search`／`transfer_to_memory` 子 agent 时，对应工具从主 agent 移除。
- 回复发送前去掉 QQ 无法显示的 Markdown 和结尾套话；回执只根据实际写入由程序生成，例如“（「聚餐」已记录）”。
- 新增 `tools/sandbox/`（移植自 GitHub 分支，适配 v0.2 以后的版本）：`--astrbot` 复用本机 AstrBot，不下载、不碰其数据；`--frontend` 切换前台；新增宿主 agent 上下文、真实工具调用、草案、确认与权限的端到端检查。

# v0.2.1 — 2026-09-28

- 修正AstrBot默认回复禁止标志，防止同一提问由宿主和插件各回复一次。
- 增加对真实宿主ProcessStage的回归，不再仅依赖模拟API含义。
- 区分群记与其他发言者的身份、能力及转述归属；默认回答更简洁，减少跑题与重复解释。
