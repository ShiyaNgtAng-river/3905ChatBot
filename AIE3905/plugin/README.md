# 群记 · AIE3905 企业群聊助手

基于讨论中的 v0.3 方案实现的 P0 程序。包含 AstrBot 插件、独立记忆核心、审核网页、离线回放、评测工具和自动测试。

它保存获准的群消息，把提议、确认、变更、取消和个人状态整理到事项账本中；回答时给出当前结论与原文依据。适合先在自己的测试群验证，再接入企业批准的环境。

**当前交付是可运行的开发版本。已验证本地流程、HTTP 服务和 AstrBot 接口模拟；尚未连接真实企业平台或真实模型服务，不能据此宣称已经达到企业场景的准确率。**

## 1. 三分钟运行

独立程序需要 Python 3.11+，建议使用 Python 3.12。核心没有第三方 Python 依赖；Windows 若缺少时区数据，需在相应环境安装 `tzdata`。AstrBot 宿主按其自己的运行要求安装。

解压后，在本目录执行：

```bash
python3 -m secretary demo
```

这会打印“产品演示改期、原因追溯、有人提出取消但未确认”的完整结果。数据临时生成、用后删除，不需要账号或模型密钥。

运行带界面的版本：

```bash
python3 tools/start_demo.py
```

1. 打开终端显示的地址，默认 `http://127.0.0.1:8765`。
2. 把终端生成的访问令牌粘贴到页面连接框。
3. 点击“导入虚构演示”。
4. 问“产品演示现在怎么定的”，再问“为什么改期”。
5. 点开事项、原文依据和待确认事件，试用确认与反馈。

演示数据保存在 `data/demo.sqlite3`。重复导入不会新增副本。需要重新开始时，先停止程序，再移除这份**演示**数据库及其附属文件。

**演示模式只识别明确记事命令和少量示例语法，不能代表自然语言理解能力。** 任意真实群聊的理解，需要配置模型。

## 2. 已实现的能力

| 功能 | 当前实现 |
| --- | --- |
| 持续接收消息 | AstrBot 消息事件监听；未被 @ 的已送达消息也能入库。只启用明确配置的群。 |
| 事项与版本 | 提议、确认、变更、取消、完成、更正、标记过时；保留证据和模型处理版本。 |
| 当前结论与回溯 | 查询事项状态与变更原因；原文双通道检索；支持同一成员的简短追问。 |
| 重要性与群报 | 优先级、阻塞、取消、更新时间排序；手动群报；AstrBot 中可配置每日定时群报。 |
| 多人状态 | 成员参加、缺席、负责、受阻；区分整个系列与指定日期的一次安排。 |
| 自然互动 | 默认被明确问到再回答；明确邀请闲聊时调用模型；配置固定风格；冲突提醒默认关闭。 |
| 人工纠正 | 记事、更正、确认、引用后“这条记住”“这个已经过时了”；回答反馈。 |
| 审核工作台 | 事项时间线、待确认事件、原文查阅、未提取消息抽查、命令入口、反馈。 |
| 数据控制 | 群隔离、Web 令牌权限、停止记录、删除及重放阻止、到期清理。 |
| 回放与评测 | JSONL 输入、按时间逐步回放、功能案例、可选全文与关键词模型基线比较。 |

首版工作回答由模型选择事实条目，再由程序呈现时间、状态、人员与依据，避免主模型在润色时把事实改坏。闲聊可以自由表达；工作结论的措辞有意保守。是否提取正确仍依赖模型和人工审核。

## 3. 切换为真实模型

支持两个入口，不绑定特定模型品牌：

### OpenAI 兼容服务

复制 `examples/local-model.config.json` 为自己的配置，例如项目根目录的 `config.json`。注意数据库路径相对**配置文件所在目录**解析。

配置：

- `models.understanding`：小模型，负责事件抽取和话题关联。
- `models.answering`：主模型，负责选择回答条目与闲聊。也可与小模型共用同一个服务。
- `base_url`：例如本机模型服务的 `http://127.0.0.1:8000/v1`。
- `model`：服务实际暴露的模型 ID，替换示例里的占位符。
- `api_key_env`：读取密钥的环境变量名；不要把密钥写入聊天或源代码。
- `json_mode`：默认要求 JSON 输出；服务不支持 `response_format` 时可设为 `false`，但模型仍必须返回可解析 JSON。

使用远端服务时需要配置 `allow_remote: true`，且使用 HTTPS；还需事先将实际处理位置纳入数据使用约定。程序不会根据聊天内容选择网络目的地，也不会跟随模型服务的 HTTP 重定向。

在 `groups` 中填写群与稳定用户 ID，确认用途和处理位置后，设置：

```json
{"enabled": true, "data_use_confirmed": true}
```

这两个字段只是运行开关，不替代实际的数据授权。生产示例默认关闭。

用 JSONL 回放验证模型：

```bash
python3 -m secretary replay --config config.json --input your-authorized-records.jsonl
```

### 复用 AstrBot Provider

使用 `examples/astrbot.config.json`，将两个 `provider_id` 替换为 AstrBot 中已经配置好的服务 ID。`mode: astrbot` 必须在 AstrBot 插件内运行；离线工具使用 `demo` 或 `openai` 模式。

模型的大小、量化、吞吐和中文群聊效果需要实测；项目不依赖 4 张 5090 先到位。

## 4. 安装到 AstrBot

本插件按本次核对的 AstrBot 4.28.1 源码接口编写，要求相应版本或兼容更新。未在此环境安装完整 AstrBot 宿主，安装后按验收清单逐项验证。

1. 将本目录作为 `astrbot_plugin_groupsecretary` 放入 AstrBot 的 `data/plugins/`，或通过支持本地 ZIP 的插件管理入口安装。ZIP 根目录包含 `main.py` 与 `metadata.yaml`。
2. 首次启用会在 `data/plugin_data/astrbot_plugin_groupsecretary/config.json` 生成空群配置。默认不读取任何群。
3. 将配置改为真实模型配置，并填写：
   - `platform_id`：AstrBot **适配器实例 ID**，不是笼统的平台名称。
   - `native_group_id`：该平台的群 ID。
   - `admins`、`confirmers`：平台稳定用户 ID，不是昵称。
   - `processing_location`：实际模型处理位置。
4. 也可以在插件配置 `config_path` 中指定自己的 JSON 配置绝对路径。
5. 重载插件。先发一条普通消息，再测试 @、引用和查询。

插件只关闭配置群的 AstrBot 默认 LLM 回复。**其他插件仍可能发言**，请在试点群只保留一条负责 AI 回复的流程。

`support_platforms` 表示面向这些适配器的接入目标，不代表已实测这些平台的权限、全量消息或撤回事件。平台端全量消息权限仍需配置；插件无法处理平台没有交付的消息。

撤回若未进入 AstrBot 普通消息事件，适配器需调用插件的 `ingest_recall(platform_id, group_id, native_id)`。已为送达的 OneBot `group_recall` 事件加了转换；飞书等平台的独立撤回桥接须实际验证。编辑消息也必须转换为带 `revision` 的 `edit` 记录，不能当作同一 ID 的新消息直接覆盖。

完整清单：[平台接入验收](docs/ADAPTER_CHECKLIST.md)。

## 5. 常用群命令

```text
/秘书帮助
/秘书状态
/事项
/问 演示现在怎么定的
/回溯 演示为什么改期
/群报 1
/原文 消息ID
/聊 今天大家都很累，说句简短的鼓励

/记事 演示 | 提议 | 时间=明天下午三点;负责人=老张;优先级=5
/记事 演示 | 确认 | 时间=2026-10-02T15:00:00+08:00
/记事 演示 | 变更 | 时间=2026-10-06;原因=数据未齐
/记事 演示 | 取消 | 原因=项目安排调整
/记事 演示 | 过时 | 备注=原安排已不适用，请重新确认
/记事 周会 | 变更 | 时间=2026-09-30T21:00:00+08:00;单次=2026-09-30
/记事 周会 | 缺席 | 单次=2026-09-30
/记事 演示 | 更正 | 目标事件=事件ID;时间=2026-10-07
/确认 事件ID

/反馈 回答ID 找错了 这次引用的是旧安排
/别记我
/恢复记录
/忘掉 事项ID 确认
```

字段使用英文分号 `;` 分开。`优先级` 范围为 1–5。`/事项` 给出事项和事件的短 ID；短 ID 必须唯一。

还可以**引用原消息**后说“这条记住”或“这个已经过时了”。记录权限和确认权限不同：普通成员提出的取消、过时或变更，不会直接覆盖正式结论。群的确认规则可选指定成员 `designated` 或事项发起人 `initiator`，不自动推断多数共识。

更正只能指向自己的事件，管理员除外。删除事项仅限管理员，且要求显式写出“确认”。

## 6. 审核页与接口

在 AstrBot 配置中开启 `web.enabled`，填写 `web.tokens`，并在宿主进程设置对应环境变量，即可同时开启工作台。独立启动使用：

```bash
python3 -m secretary serve --config config.json
```

`serve` 明确表示启动工作台，不受 `web.enabled` 的 AstrBot 开关限制；但始终要求有效令牌。访问令牌至少 24 字符，建议使用随机生成值。默认只绑定本机，不提供公网服务；远程访问可以使用 SSH 隧道。

同一数据库只能有一个运行中的 Engine。**不要同时启动独立服务和 AstrBot 来写同一份数据库。** 需要一起使用时，由插件内部启用审核页。

所有 API 用 `Authorization: Bearer <token>`，请求中的 `group` 必须在该令牌的群列表中。

| 接口 | 用途 |
| --- | --- |
| `GET /api/groups` | 可访问群 |
| `GET /api/items?group=...` | 事项状态、有效历史、待确认事件 |
| `GET /api/messages?group=...` | 最近 100 条获准原文，供抽查 |
| `GET /api/message?group=...&id=...` | 单条依据 |
| `GET /api/status?group=...` | 处理状态与全部模型调用统计 |
| `GET /api/feedback?group=...` | 管理员读取反馈 |
| `POST /api/query` | `group`、`question`，可选 `report_days` |
| `POST /api/command` | `group`、`text`，执行同一套命令 |
| `POST /api/feedback` | `group`、`answer_id`、`kind`、`note` |
| `POST /api/ingest` | 管理员导入标准消息，字段见下节 |
| `POST /api/demo` | 仅规则演示环境导入虚构数据 |

## 7. 导入群历史

每行一个 JSON 对象。最小例子：

```json
{"group":"pilot","native_id":"msg-102","sender":"u-17","name":"小林","at":"2026-09-27T09:00:00+08:00","text":"之前的演示改到周二了吗？","reply_to":"msg-100"}
```

- `sender` 必须是稳定 ID；只有昵称的导出，先人工映射，不自动猜同名身份。
- `at` 必须包含时区；`name` 仅用于展示。
- `reply_to` 指向同群消息的原生 ID。
- 图片先保留 `attachments: [{"type":"Image","processed":false}]`；首版不会猜图中内容。
- 没有原生 ID 时，回放工具按文件摘要和行号生成稳定替代 ID。修改或重排文件会改变该身份；跨导出检测到的内容重复只做标记，不擅自删除可能真实重复的发言。
- 撤回记录使用独立的 `native_id`、`kind: recall` 和 `target_id: 被撤回的原消息ID`。
- 编辑记录使用原消息 `native_id`，再给 `kind: edit` 和新的 `revision`。

```bash
python3 -m secretary replay --config examples/demo.config.json --input examples/replay.jsonl
```

历史导出工具、获准范围和字段缺失，必须随数据一起记录。插件没有提供绕过平台权限的采集器。

## 8. 测试与比较

运行自动测试：

```bash
python3 -m unittest discover -v
```

回放独立的功能案例：

```bash
python3 -m secretary.evaluate --config examples/demo.config.json --input examples/replay.jsonl --cases examples/cases.json --output evaluation.json
```

使用真实模型时增加 `--compare`，会在同一批案例上比较本方案、全文输入和关键词检索，分别记录耗时和模型用量，并提供按独立事项抽样的配对 bootstrap 区间。

**这里的自动评分是明确的内容断言与来源 ID 检查，不是完整的语义评测。** 结果需要人工复核；全文基线超过预设预算会报错，不静默截断；合成数据上的通过率不能当作企业验收结果。

本次验证记录：[TEST_REPORT.md](docs/TEST_REPORT.md)。

## 9. 数据边界与尚未完成的部分

`/别记我` 清理本插件保存的该成员发言及依赖内容，停止后续记录；不自动识别其他人的所有转述。`/忘掉` 删除该事项证据及派生内容，相关回答与反馈会保守清除，并用摘要标记防止相同证据重放恢复。曾引用同一条证据的其他事项也可能变为不确定。

到期清理在在线服务中每 30 秒检查；离线回放和评测不自动按当前日期清理历史样本。删除覆盖当前数据库中的记录与索引，不代表操作系统备份、平台消息、AstrBot 日志、其他插件或模型服务端的副本已经删除。它们需要单独纳入数据约定。本插件不训练权重。

后续需要完成或实测：

- 真实飞书 / QQ 全量消息、引用、撤回、编辑和断线恢复；每个平台的来源深链接。
- 自然语言模型在目标群里的提取准确率、发言体验、容量和总成本。
- 向量召回和行业分词优化；当前原文使用支持中文二元词片的 SQLite FTS5 / BM25 召回，SQLite 未提供 FTS5 时回退为全文关键词扫描。
- 多模态识别：当前仅标记尚未处理的附件。
- 复杂周期日历、自动共识、跨群查询；本版不自动开展这些操作。
- 基于足够反馈的监督微调 / LoRA / RL，以及策略的离线比较与回退。

工程说明和扩展位置：[ARCHITECTURE.md](docs/ARCHITECTURE.md)。企业场景的接口、模型和数据使用范围，需要由双方实际确认后接入。
