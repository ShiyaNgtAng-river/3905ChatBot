# v0.3 宿主配置草案（待确认后应用）

插件侧（第 1、3 阶段）已完成并通过测试。下面是 AstrBot 宿主要做的配置。它们都写在 `data/cmd_config.json` 或 WebUI 的人设管理里，必须在 AstrBot **停止后**修改，或者直接在 WebUI 里操作。Key 只由本人在 WebUI 填写。

## 1. 子 agent（前置路由 → 搜索 / 记忆）

WebUI →「配置」→「子智能体」，或 `cmd_config.json` 中的 `subagent_orchestrator`：

```json
{
  "main_enable": true,
  "remove_main_duplicate_tools": false,
  "router_system_prompt": "需要联网查外部信息（时事、网页、仓库、产品、需要核实的事实）时交给 transfer_to_search；需要回忆本群以前的聊天、某人说过什么、某段时间发生了什么时交给 transfer_to_memory；两类都需要就都调用。交接时把要查的人、时间、关键词写清楚。拿到结果后用你自己的口吻简短转述，不照搬格式。闲聊、写东西、出主意直接回答。",
  "agents": [
    {
      "name": "search",
      "enabled": true,
      "public_description": "联网搜索：时事、外部知识、网页/仓库/产品介绍、需要核实的事实。输入写清要查什么。",
      "system_prompt": "你是搜索助手。用 web_search_bocha 查资料，summary 设为 true。一次查不到就换关键词再查 1–2 次，交叉核对 2–3 个来源。只输出要点：结论、关键事实、日期、最多 3 个来源链接。查不到或说法冲突就直说。不要寒暄。",
      "tools": ["web_search_bocha"]
    },
    {
      "name": "memory",
      "enabled": true,
      "public_description": "群聊记忆：群里以前说过什么、谁说的、某段时间聊了什么、某个成员的情况。输入写清人、时间、关键词。",
      "system_prompt": "你是群聊记忆助手，只能依据本群记录回答。先用 get_group_episodes 了解大致时间和话题，再用 search_group_history 查原话（可按 who、when 过滤），需要时用 get_member_profile。结论注明出处（时间和发言人）。找不到就说只找到了什么，不要编。只输出要点，不要寒暄。",
      "tools": ["search_group_history", "get_group_episodes", "get_member_profile"]

```

- 插件会在配置群的 @ 轮次，把 `web_search_*` 和三个记忆工具从主 agent 身上移走，主 agent 只能通过 `transfer_to_*` 调用它们。所以 `remove_main_duplicate_tools` 不用打开。
- 子 agent 可以单独指定 `provider_id`，用 flash 就够；主 agent 可以换成更强的对话模型。

## 2. 联网搜索（博查）

WebUI →「配置」→「网页搜索」：打开搜索，服务商选 **bocha**，在 `websearch_bocha_key` 里填你自己的 Key。

## 3. 人设（等你提供角色设定）

WebUI →「人格」新建一个人设，并设为默认，至少设为测试群会话的默认。请提供：

| 项 | 例子（参考“爱音”） |
| --- | --- |
| 名字与自称 | 爱音 / “爱音” |
| 性格、说话方式 | 活泼、爱用“～”，1–3 句为主 |
| 怎么称呼群友 | 直接叫昵称 |
| 口头禅（可选） | |
| 不聊的话题、边界 | 群公告禁止的话题要温和提醒 |
| 3–5 段示例对话 | 用作 begin_dialogs 少样本 |

写人设时我会补上几条固定规则：
- 回答以 1–3 句为主，不用 Markdown，结尾不追问；
- 用了工具就用角色口吻转述，例如“我刚翻了下聊天记录…”“我搜了一下…”；
- 技术问题交给搜索子 agent 去查，不能像参考记录里那样用“技术活不归我管”拒答；
- 不冒充具体的真人群成员，不编造和群友的共同经历；
- 正式事项以工具回执为准。

## 4. 分段回复

`platform_settings.segmented_reply.enable = true`，默认按句号、问号、感叹号、～、… 切分。QQ 官方机器人对同一条消息能发的被动回复条数可能有限制，先在测试群观察，必要时调大 `words_count_threshold`，少分几段。

## 5. 部署顺序

1. 正常停止当前 AstrBot（先确认端口 6185 已释放）。
2. `.venv/bin/python tools/deploy_plugin.py --host /Users/tangshiyang/CUHKSZ/AstrBot/AstrBot-master --config config/qq.json`，脚本会先备份。
3. 修改上面 1、2、4 项（或者启动后在 WebUI 里改）。
4. 带日志启动：`cd /Users/tangshiyang/CUHKSZ/AstrBot/AstrBot-master && uv run --no-sync main.py 2>&1 | tee astrbot-run.log`。
5. 在测试群依次验证：闲聊、技术问题（应触发搜索）、“上周谁说过…”（应触发记忆）、设计方案 → 修改 → 确认人确认 → 查询。

回退：把插件配置里的 `dialogue.frontend` 设为 `plugin`，恢复 v0.2 的对话路由；或关闭 `subagent_orchestrator.main_enable`。
