# 调研：拟人化与群聊全局理解

本文整理两部分调研：

1. 让群聊机器人更“像人”：亲切、自然，不带助手腔。
2. 让机器人对高频群聊有“全局理解”：一天之内交错的多个话题能理解成一个整体，关键信息能保留几周到几个月。

后面给出这些结论落到群记插件（AstrBot）上的做法、已完成的部分和待办。

---

## 一、拟人化

### 1. 目标拆解

“像人”不是一件事，至少可以分成四层：

| 层 | 含义 | 反例（机器人味） |
|---|---|---|
| 人格 | 稳定的性格、价值观、说话习惯 | 每次回答口吻不同，或者没有口吻 |
| 关系 | 记得对方是谁、说过什么、彼此的熟悉程度 | 对老成员和新人说一样的客套话 |
| 语境 | 接得住群里正在聊的话题和梗 | 答非所问、把两个话题混在一起 |
| 表达 | 长短、节奏、语气词、群里的说法 | 固定“首先…其次…希望对你有帮助” |

### 2. 相关工作与结论

- **人设提示本身就很强**：Jones & Bergen 的图灵测试研究中，带详细人设提示的大模型被判为人类的比例达到 73%，没有人设时则明显更低。结论是“像人”首先是提示工程问题，不必一开始就训练模型。
- **把人格、记忆、风格拆开处理**：Test-Time-Matching 这类工作把角色扮演拆成三个可以分别控制的部分：性格设定、角色记忆、语言风格。对应到我们这里：人设文件负责性格，插件的记忆负责“记得谁说过什么”，风格靠示例对话和群里的说法。
- **向群友学表达**：MaiBot 等开源群聊机器人从群聊里学习“什么场合、群友怎么说”和黑话，再注入回复。效果明显，风险是学到不该学的内容，所以需要人工可见、可删。
- **评测**：CharacterEval 等角色扮演评测把“角色一致性、对话能力、吸引力”分开打分。我们的线上指标对应为：助手腔出现率（`style_flags`）、开头和结尾的重复率、回复长短分布，外加人工盲评。
- **训练路线**：用 DPO 等偏好优化训练“更像人”的回复有效，但需要成对的偏好数据和自有模型。当前阶段不做，先把提示、记忆、过滤做好。

### 3. 落地（已上线）

- 默认人设换成更亲切的“千早爱音”；示例对话覆盖打招呼、被重复提问、被骂、做不到的事、深度问题等场景。
- **说话人印象**：@ 时注入“你对他的印象”，只来自本群公开发言，退出记录的成员不会出现。
- **助手腔过滤和统计**：
  - 去掉 QQ 显示不了的 Markdown、调用工具前的“我查一下”、服务式道歉和“希望对你有帮助”之类的结尾；
  - “作为 AI”和解释自身能力的句子只计数不删，避免删掉后语义断开，也不隐藏 AI 身份。
- **回答深浅按意图判断**：日常问题一两句；专业问题或说了“仔细/深入/详细”时交给搜索子 agent 深度调研。
- 不主动插话。

### 4. 待办

- 用 `style_flags` 和回复记录做线上统计，定期人工看一批回复。
- 表达样例：从群聊中挑出典型的应对方式作为样例。现在只做了黑话和“聊天风格”一句话，完整的样例还没做，要先确认不会学到不当内容。

## 二、群聊全局理解

### 1. 问题

旧方案每 30～40 条切一批，逐批做摘要或话题归属。固定窗口只能看到局部，**局部拼不出全局**：

- 一个话题被别的话题打断后，前后两段被当成两件事；
- 改期、推翻的决定分散在不同批次里，看不出“现在以哪个为准”；
- 几周前的事只剩一段越传越偏的摘要。

### 2. 相关工作

- **对话分离**：把交错的群聊拆成多个线程，经典做法是两步：先判断每条消息在回复谁，再聚成线程。群聊平台的“回复/引用”和 @ 本身就是第一步的强信号。
- **时间线摘要**：对随时间演变的事件做时间线式摘要，比一段总摘要更适合回答“怎么变过来的”。
- **带有效期的记忆**：Zep/Graphiti 给每条事实记下生效时间和失效时间，新事实推翻旧事实时不删旧的，只标失效，因此既能回答“现在是什么”，也能回答“三周前是什么”。
- **分层结构回答全局问题**：GraphRAG、RAPTOR 等工作说明，“整体在讲什么”这类问题的答案不在任何单个片段里，要靠预先做好的分层摘要。
- **长期对话记忆评测**：LongMemEval 把能力分为信息抽取、多会话推理、时间推理、知识更新和拒答五类；LoCoMo 评测跨几十次会话的长期对话。我们的离线评测按这几类设计题目。
- **长上下文 vs 检索**：Self-Route（EMNLP 2024）的结论是，资源允许时，把内容整体放进长上下文通常优于检索片段，检索适合作为便宜的补充路线。
- **长上下文的缺陷**：Lost in the Middle（TACL 2024）发现模型容易忽略长上下文中间的内容。应对办法是把关键指令放在首尾、先压缩噪音、提供结构骨架。
- **前缀缓存**：DeepSeek 默认开启上下文硬盘缓存，前缀相同的部分按命中价格计费，用量里有 `prompt_cache_hit_tokens`。反复读同一段只追加的记录会很便宜。
- **提前计算**：sleep-time compute 的思路是空闲时先把可预期的问题算好，回答时直接用。Generative Agents 按“新近、重要、相关”打分挑选记忆，并定期反思、提炼；MemGPT 把记忆分成常驻的主存和按需取用的归档。
- **率失真视角**：把记忆看成有预算的有损压缩。它的核心警告是：不知道将来会被问什么时，提前丢掉的信息无法挽回。所以原文要保留，只压缩从原文派生出来的内容。

### 3. 关键数字

- 群消息平均约 18 字，加上昵称和时间约 30 token 一行。500～3000 条一天约 1.5 万～9 万 token，而 flash 和 V4-pro 的上下文窗口都是 100 万 token，**一次就能读完一整天**。
- 前缀缓存让“每隔一段时间把当天全文重读一遍”的成本主要落在新增部分上。

### 4. 设计（v2，已实现并部署）

一句话：后台通读群聊建目录和长期记忆，@时注入，让回复懂全局。

- **原文保留**：从原文派生出来的内容都能从原文重算；删除原文时，只删掉引用了它的派生条目。
- **当天通读**：
  - 按新增字数或空闲时间，把当天全文从头读一遍，生成“话题 × 时间”的当天目录，每个要点都必须引用真实的消息编号；
  - 提示按“固定指令与 QA 清单 → 只追加的当天全文 → 上一版目录和长期话题”排列，以命中缓存；
  - 表情、笑声、复读先用规则合并，回复关系写在每行末尾。
- **按问题读**：由有经验的人维护 QA 清单（`config/qa_list.json`），包括今天的话题、结论、计划变化、推翻、未决问题、黑话、分工、情绪、对助手的反馈、关键事实。清单在提示开头和结尾各出现一次。换到维修厂等场景时，主要改这份清单。
- **日终整合**：每天凌晨对前一天：
  - 逐条回答 QA 清单，生成日摘要；
  - 长期记录只接受由程序校验的操作：话题、决定/计划/事实、推翻（只限同一话题）、未决问题及其答复、成员分工、群里的说法、聊天风格。
  - 用操作而不是整段改写：不会越传越偏，可以追溯来源，也可以按来源删除。
- **衰减与归档**：话题得分 = 新近程度（半衰期 14 天）+ 模型评的重要度 + 出现天数。长期不提的话题归档，不再注入，但工具仍能查到，再次被提起时恢复。
- **分层取用**：
  - 每次 @ 时，今天的话题、相关的长期记录和群里的说法放在提示最前面，全部是数据库查询，不增加等待；
  - 更深的问题由 memory 子 agent 按“话题时间线 → 日/周/月摘要 → 原话检索 → 重读某一天”的顺序查找。
- **不用向量检索（暂时）**：全局问题、时间先后和否定句正是向量检索的弱项，找细节用全文检索就够。以后能在本地部署 bge-m3 类模型时，再用它做跨月话题匹配。
- **正式事项仍然是权威**：长期记录只算“观察到的非正式状态”；两者冲突时以正式事项为准。逐条提取正式事项前先过一道筛选，只把可能含事项的消息交给模型。

### 5. 评测

- `python3 lab.py days` 生成多天的虚构群聊和标准答案：多话题交错、跨天改期、换地点、取消、分工、问答、黑话、复读和大量闲聊。
- `python3 tools/eval_memory.py --baseline` 按模拟时钟回放，并与原来的固定窗口话题摘要对比。评测项包括：
  - 当天的话题和决定；
  - 当前状态，以及当前记录里有没有残留已被推翻的旧说法；
  - 能否查到历史说法；
  - 回复时能否看到当前结论；
  - 黑话、分工、答案是否保留，没讨论过的事能否拒答；
  - 每千条消息的成本和缓存命中率。
- 局限：按关键词核对，不等于人工语义评分；模拟群聊比真实群聊规整。真实模型的评测结果尚未产出，需要在自己的终端输入 Key 运行。

### 6. 待办

- 跑真实模型评测，根据结果调整通读频率、QA 清单和注入预算。
- 保留期从 30 天调到 180 天：先在群里告知，再改配置。在此之前，长期记录最多保留约 30 天。
- 表达样例（见第一部分）。
- 视评测结果决定日终整合是否可以从 V4-pro 降到 flash。
