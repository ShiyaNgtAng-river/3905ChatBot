## 真实 DeepSeek 测试与修复

测试只使用虚构的“集成测试评审”消息，未发送到 QQ，也没有把真实群聊输入诊断脚本。

首次链路测试：API 可达并输出 JSON，但三条消息中两条失败。模型以 JSON null 表示无 target，原校验却用 str(null) 形成非空目标 ID，引发“目标事件不存在”。另有普通改期被解释为 occurrence 的提示词歧义。

修复：null target 作为无目标处理，其他非字符串类型仍拒绝；明确普通提议、确认、改期使用 series，具体日期本身不构成 occurrence。

修复后真实模型测试：三条消息均为 done，最后状态 confirmed，负责人老张，日期 2026-10-06，原因“样本尚未备齐”，回答附三条来源。该次引擎共 4 次请求、2740 输入 token、369 输出 token。仅此小样本通过，不代表总体自然语言准确率。

新增三项离线回归：null 可接受、未知非空 ID 仍拒绝、null 不授予确认权限。连同原有核心与适配器契约测试，本轮 36 项通过；此数字不包含 HTTP 组。

已安装修复文件：`secretary/memory.py`、`secretary/extract.py`。旧文件和配置备份位于宿主 `data/groupsecretary_backups/20260928-110515/`。备份可能含原有凭据，目录已限制权限，不进入项目交付包。
