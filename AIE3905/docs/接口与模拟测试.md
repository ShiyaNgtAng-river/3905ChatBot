# 接口与模拟测试

## 1. 沿着一次消息读代码

先看 `plugin/main.py` 的 `observe`：取得平台实例、群、成员、消息 ID 和引用；映射到配置群，再交给 `Engine.ingest`。只有指定群会记录，普通消息不要求 @ 机器人。

然后依次阅读：

| 文件 | 你要理解的问题 |
| --- | --- |
| `secretary/types.py` | 一个 Message 有哪些字段，稳定 ID 为什么必需 |
| `secretary/config.py` | 配置如何变成群范围、确认人、模型和数据库路径 |
| `secretary/engine.py` | 消息如何入队、重试、排空、查询、关闭 |
| `secretary/extract.py` | 明确命令与自然语言如何转成候选事件 |
| `secretary/memory.py` | 权限和来源如何校验，事件如何投影成当前状态 |
| `secretary/answer.py` | 模型如何选择事实，程序如何呈现回答 |
| `secretary/providers.py` | 模型请求的真实 HTTP 边界与宿主 Provider 边界 |
| `secretary/store.py` | SQLite 原文、事件、状态与用量如何存储 |
| `secretary/web.py` | 本地审核 API 的认证与群权限 |

以上路径均相对 `plugin/`。不要先把多个模块拆成微服务；当前是一个有异步队列的进程。

## 2. 消息接口与生命周期

模拟 JSONL 中每行只放一条消息：

```json
{"group":"lab","sender":"owner","name":"老张","text":"模拟评审001正式改到2026-10-15，原因是样本尚未备齐。","at":"2026-09-28T09:01:00+08:00","native_id":"s1-3","reply_to":""}
```

`sender` 是稳定身份；`name` 只是昵称。`group` 是内部 key。`at` 必须带时区。`reply_to` 使用被引用消息的原生 ID；它与事件 ID、内部消息 UID 不是同一种东西。

撤回记录用新的唯一 ID 指向旧消息：

```json
{"group":"lab","sender":"owner","text":"","at":"2026-09-28T09:02:00+08:00","native_id":"s1-6","kind":"recall","target_id":"s1-3"}
```

核心调用顺序是：`Engine(Config(...))` → `await start(maintenance=False)` → `ingest(Message(...))` → `await flush(group)` → `query(Actor(...), group, question)` → `await close()`。

`ingest` 表示原文已接收，不等于模型已经理解。`flush` 等待 pending／retry 排空，但失败记录也会结束重试，所以必须同时检查状态计数。主要状态包括 done、pending、retry、failed、unstructured 和 unparsed_attachment。

在线服务需要数据清理等维护任务；离线历史回放关闭 maintenance，避免旧合成数据因保留期被清理。数据库只允许一个活动写入进程；评测使用临时库。

## 3. 本地审核 API

除静态页面资源外，API 都使用 `Authorization: Bearer 工作台令牌`；不是云模型 Key。默认只绑定本机。

| 方法 | 路径 | 参数与用途 |
| --- | --- | --- |
| GET | `/api/groups` | 当前令牌允许的群 |
| GET | `/api/status?group=lab` | 处理状态、事项数、用量 |
| GET | `/api/items?group=lab` | 当前事项与事件历史 |
| GET | `/api/messages?group=lab` | 最近 100 条原文抽查 |
| GET | `/api/message?group=lab&id=消息ID` | 一条具体依据 |
| GET | `/api/feedback?group=lab` | 反馈记录，需管理权限 |
| POST | `/api/query` | `group`、`question`，可选 `report_days` |
| POST | `/api/command` | `group`、`text`，执行助手命令 |
| POST | `/api/ingest` | `group`、`message`；管理权限下导入 Message |
| POST | `/api/feedback` | `group`、`answer_id`、`kind`、`note` |
| POST | `/api/demo` | `group`；仅 demo 模式、管理员可用 |

示例：在自己的终端隐藏输入页面令牌，再调用查询。

```sh
read -s 'GROUPBOT_ADMIN_TOKEN?工作台令牌: '
printf '\n'
export GROUPBOT_ADMIN_TOKEN
curl -s http://127.0.0.1:8765/api/query \
  -H "Authorization: Bearer $GROUPBOT_ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"group":"lab","question":"产品演示现在怎么定的？"}'
```

`/api/ingest` 仅是实验与管理入口，没有 QQ 登录、平台签名或完整的 OneBot 协议语义。

## 4. 模拟数据怎样生成

```sh
./run generate --seed 42 --scenarios 2 --noise 0.8 --style commands --output datasets/demo-noise80
./run generate --seed 42 --scenarios 2 --noise 0.8 --style natural --output datasets/natural-noise80
./run generate --seed 43 --scenarios 4 --noise 0.9 --style natural --hard --output datasets/hard-noise90
```

每个事项有六个阶段：提议 → 引用确认 → 改期 → 单次缺席 → 无权限取消建议 → 撤回改期。多个事项交错，但每个事项内因果顺序不变。不同标题避免已知的同名合并问题，因此本数据不覆盖该缺陷。

噪音比例指噪音条数除以总条数。例如两事项共 12 条任务消息，80% 噪音需要 48 条噪音，合计 60。取整后的实际比例记录在 manifest。

普通噪音含闲聊、表情、无关订单和游戏话题；`--hard` 增加引用过时结论、无明确引用的“可以”、图片占位、要求模型忽略规则的消息。图片只是占位，用于测试“不猜图”，没有测试视觉识别能力。

| 文件 | 是否送给待测系统 | 内容 |
| --- | --- | --- |
| `messages.jsonl` | 是 | 消息、身份、时间与引用；不含正确答案 |
| `cases.json` | 否，只给评分器 | 每个检查点的问题、期望状态、字段与来源断言 |
| `manifest.json` | 不作为模型提示 | 种子、噪音比例、条数、风格、内容摘要 |

相同种子和参数可复现完全相同文件。只切换 commands／natural 时，检查点与期望相同，消息文字不同。命令版绕过大部分语言理解，只测记忆与权限；自然语言版必须用真实模型评测。

## 5. 回放与结果解释

```sh
./run bench --config config/demo.json --dataset datasets/demo-noise80 --output results/demo-noise80.json
./run bench --config config/qwen.json --dataset datasets/natural-small --output results/qwen-small.json
```

每次新建临时库，按时间只投递问题出现之前的消息，排空队列后回答，再继续后续消息。未来的确认或撤回不会提前提供给模型。`cases.json` 不会进入理解／回答提示。

本工具默认对云模型设置保守的请求次数预算：`消息数 × max_attempts + 问题数`，超过默认 120 时拒绝开始。需要扩大实验时显式增加 `--max-calls`，例如 300；这不是金额预算。使用 `--timeout` 调整每批等待时间。

| 指标 | 解释与限制 |
| --- | --- |
| `state_assertion_pass_rate` | 标题、状态、指定字段、缺席或字段清除断言通过比例 |
| `answer_assertion_pass_rate` | 必须包含／不能包含的片段与必需原文 ID 检查；部分状态阶段没有文字约束，应结合状态分数 |
| `processing_failures` | failed／pending／retry 消息数量，不能被排空完成掩盖 |
| `message_status` | 展示普通规则噪音的 unstructured 与真正失败的差异 |
| `usage` | 服务回传的请求次数、输入／输出 token 和耗时；不是人民币费用 |
| `answer_latency_p50/p95_seconds` | 排空抽取队列之后的回答延迟；不含 QQ 网络时间 |
| `replay_messages_per_second` | 串行回放总吞吐，包含查询与排空开销；不是压测最大容量 |
| `cases` | 每个案例的判分、实际回答、来源及耗时；人工复核入口 |

自然语言模型可能改写事项标题，精确标题断言会失败；这应人工查看是身份关联错误还是可接受别名。不要只盯住一个总分。

## 6. 怎样设计有说服力的实验

固定模型参数、确认人和时间语义，在 0%、50%、80%、90% 噪音下使用同一组任务事实；每档运行多个种子。先用少量场景检查标注，再扩大。参数调试使用一组种子，最终报告使用未参与调试的种子；模板相同的多个种子仍不等于独立真实语料。

至少分开报告：事项归属、提议／确认、短回复、个人状态、撤回、更正、引用来源与时间歧义。当前自动生成器覆盖前六阶段的基础子集；更正漏洞、周期、同名事项等应另建失败集。不要为了获得通过率删除已知失败案例。

原项目的 `plugin/secretary/evaluate.py --compare` 提供完整历史／关键词原文基线，以及按事项聚类的配对比较。它的自动评分仍是字符串断言，输入 cases 需符合原评测器格式；新生成 cases 的常用字段兼容，但其额外 `expected_state` 不会被原评测器检查。涉及模型的基线比较会额外产生调用。

自然语言数据中的六阶段是人工预设的合成模板；现有通过结果只能表明工程链路在这些案例上成立。最终性能结论需要扩展表达、多轮歧义、独立人工标注，并保留失败例子的原文证据。

## 7. v0.2 自然对话接口

新增 `POST /api/dialogue`，沿用工作台令牌认证。示例请求：

```json
{"group":"lab","text":"帮我们设计两套会议安排","request_id":"test-turn-001"}
```

可选 `reply_to` 为原文消息ID、返回的回答ID或草案ID。调用者身份来自令牌，不能通过请求体的 sender/admin 修改。一个新请求使用一个稳定ID，网络重试复用它；更换文本须使用新ID。

返回 `id`、`text`、`sources`、`drafts`、`operations`、`mode`、`ready`。`operations[].status` 为 `recorded` 或 `pending_confirmation`；`drafts` 是建议，不能作为正式确认。`mode=dialogue_fallback` 表示没有正常完成整段对话，仍须检查实际操作回执，部分写入可能已经完成。

Python入口：`await engine.dialogue(actor, group, text, request_id="stable-id", reply_to="")`。平台适配器传入原始 Message，同时在 `ingest(message, route="dialogue")` 时将其排除出后台提取队列；普通消息保留默认路径。

自然对话仍使用 `models.answering`；配置 `dialogue.enabled=false` 回退为原有查询入口。现有网页“问一问”保持严格查询；可在命令框输入 `/聊 帮我设计会议方案` 体验新对话，或者直接调用新API进行可重复测试。

新多轮噪音回放：

```sh
.venv/bin/python tools/replay_dialogue.py --config config/deepseek.json --noise 0.5 --seed 42
```

`datasets/dialogue-small/scenarios.json` 定义7轮任务及可观察结果断言；脚本以固定种子插入闲聊噪音。默认50%噪音，可改0.8或0.9。`--max-calls` 检查保守调用上界，超过即停止；不会擅自扩大API预算。结果写入 `--output` 指定路径，临时库随测试清理。该脚本需要真实LLM才能评估自由对话，demo模式仅可检查运行与退路，不能以它的通过率评判模型。
